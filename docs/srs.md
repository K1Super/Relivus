# Relivus 需求规格说明书（SRS）

| 文档版本 | 更新日期 | 状态 |
|---|---|---|
| v1.0 | 2026-09-18 | 正式 |

## 1. 引言

### 1.1 目的

本文档定义 Relivus 测试数据生成与数据脱敏系统的功能需求、非功能需求、数据需求与验收标准，作为设计、开发与测试的共同契约。系统定位为单用户内部工具，不涉及 RBAC、登录、SSO、多租户等企业级身份与治理能力。

### 1.2 范围

本文档覆盖以下能力范围：

- 目标数据库连接管理（密码加密存储）。
- Schema 内省（表、列、主键、外键、唯一索引、CHECK、ENUM）。
- 测试数据生成引擎（含基于 OpenAI 兼容协议的 AI 列级生成）。
- 数据脱敏引擎（多种算法与跨表一致性保证）。
- 统一任务管理与 SSE 实时进度推送。
- 审计日志、Bearer Token 鉴权、机密加密与错误码规范。

不在范围内：目标库的结构变更、生产数据迁移、多用户权限体系、容器化部署。

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| 元库（Meta DB） | Relivus 自有数据库，存储连接、任务、日志、脱敏映射、审计与 AI 配置等元数据 |
| 目标库（Target DB） | 用户在连接管理中配置的 MySQL / PostgreSQL 库，作为内省、生成、脱敏的操作对象 |
| 内省（Introspect） | 通过 JDBC 元数据接口读取目标库的表结构、约束与类型信息 |
| DAG | 有向无环图，用于表达表间外键依赖关系 |
| SSE | Server-Sent Events，服务端向浏览器推送实时进度的单向通道 |
| 脱敏映射 | 脱敏过程中原始值（哈希）与脱敏结果值的对应关系，跨表保持一致性 |
| 幂等 | 同一请求携带相同幂等键重复提交时仅产生一次副作用 |

## 2. 总体描述

### 2.1 产品定位

Relivus 是一套面向数据库开发与测试的内部工具：对目标库执行 Schema 内省，依据列类型、约束与列名启发式自动生成可信的测试数据；同时提供数据脱敏能力，将目标库中的敏感字段批量替换为不可逆或可逆的伪装值，保证测试环境的可用性与隐私安全。

### 2.2 目标用户与使用场景

| 用户 | 使用场景 |
|---|---|
| 测试 / 开发工程师 | 为联调库批量生成结构合法、外键有效的测试数据 |
| DBA / 运维 | 验证 SQL 性能、索引效果，准备脱敏后的仿真数据集 |
| 质量 / 交付人员 | 产出可审计、可复现的数据准备与脱敏记录 |

### 2.3 运行环境

| 类别 | 要求 |
|---|---|
| 运行时 | OpenJDK 17 |
| 元数据库 | MySQL 8.0 或 PostgreSQL 16 |
| 目标数据库 | MySQL 8.0 / PostgreSQL 16（由用户配置） |
| 前端 | 现代浏览器，经 Nginx 反向代理访问 |
| 部署形态 | 裸机 / systemd + Nginx，无 Docker 部署 |
| 最低资源建议 | 8GB 内存起步 |

## 3. 功能需求

### 3.1 FR-01 连接管理

- **描述**：管理系统维护的目标库连接信息，密码以 AES-GCM 密文存储于元库，支持连通性测试与动态数据源。
- **主要输入**：连接名称、数据库类型（mysql / postgresql）、主机、端口、库名、用户名、密码。
- **处理规则**：
  - 连接名称唯一，仅支持 MySQL 与 PostgreSQL；其余类型抛 `110002`。
  - 密码使用 AES-GCM 256 加密（密钥来自 `RELIVUS_AES_KEY`，Base64 32 字节），存储格式为 `Base64(IV + cipherText + tag)`。
  - 连通性测试需实际建立 JDBC 连接；失败抛 `110001`。
  - 目标库数据源由连接 ID 动态创建并缓存，密码解密后仅在内存中短暂存在。
- **输出**：连接列表 / 连接详情 / 测试结果（成功或失败原因）。
- **约束**：密码绝不以明文落库、不进入日志与响应；目标库不执行 Flyway 迁移。

### 3.2 FR-02 Schema 内省

- **描述**：对目标库执行结构内省，产出表、列、主键、外键、唯一索引、CHECK 与 ENUM 元数据。
- **主要输入**：连接 ID、表名、方言信息。
- **处理规则**：
  - 通过 `DatabaseMetaData` 读取表、列、主键、外键、索引信息。
  - CHECK 仅解析 `IN (...)` 与 `col >= x AND col <= y` 两种形式；多列或复杂表达式标记为 `UNKNOWN`，不参与过滤但写入任务日志。
  - ENUM 按方言解析：MySQL 取 `information_schema.COLUMNS.COLUMN_TYPE`，PostgreSQL 取 `pg_type` + `pg_enum`。
  - 内省结果使用 Caffeine 缓存（最大 100 表、10 分钟过期）。
- **输出**：表列表、表详情（列 / 约束）、字段依赖图。
- **约束**：内省失败抛 `120001`；不支持的数据库抛 `110002`。

### 3.3 FR-03 测试数据生成（含 AI）

- **描述**：基于内省结果按表生成指定行数的合法测试数据，支持列级生成器配置与 AI 生成降级。
- **主要输入**：连接 ID、每表行数（单表 1–500000）、列生成器配置、采样策略（UNIFORM / ZIPF）、生成前是否清空表、批大小（默认 1000）。
- **处理规则**：
  - 依外键构建表依赖 DAG 并做拓扑排序；循环依赖仅支持外键可空（否则抛 `130003`），采用两阶段插入。
  - 列级生成按决策链执行：用户配置 > 自增跳过 > 外键 > ENUM > CHECK > 主键 > 列名启发式 > 类型默认。
  - 父表插入回填自增主键，子表外键引用回填 ID；外键采样采用分页或蓄水池方式，禁止全量加载父表主键。
  - 唯一约束双层保障：数据库唯一约束兜底 + 本地 Caffeine LRU（仅缓存最近 10000 个值）；冲突重试最多 100 次，低基数列 10 次仍冲突抛 `130002`。
  - 批量插入使用 `JdbcTemplate.batchUpdate`，批大小默认 1000。
  - AI 列级生成基于 OpenAI 兼容协议（baseUrl + apiKey + model），每批请求 64 个值；仅 5xx / IO / 超时重试最多 3 次；失败降级为本地 DataFaker 假值并写 WARN 任务日志。
- **输出**：异步生成任务 ID，生成结果（处理行数、成功率）与 SSE 进度。
- **约束**：主链路无 AI 也可运行；生成必须保证外键 100% 有效、唯一约束 0 冲突。

### 3.4 FR-04 数据脱敏

- **描述**：对目标库敏感字段执行脱敏，保证同组同原始值跨表映射一致，并验证 JOIN 一致性。
- **主要输入**：连接 ID、表与列脱敏配置（算法、参数、列分组、密钥版本）、任务参数。
- **处理规则**：
  - 算法 SPI：FixedMask、RegexMask、HmacHash、PhoneMask（前 3 后 4）、IdCardMask（前 6 后 4）、BankCardMask（前 4 后 4）、FakerReplace。
  - `GlobalMaskingContext` 以「缓存 + 映射表回退」保证同一原始值同组跨表结果一致；派生键为 SHA-256 十六进制。
  - 关联列分组：外键关联、同名列、用户显式指定、复合键元组。
  - JOIN 一致性验证采用临时快照方案：脱敏前对目标行采样保存，脱敏后执行相同 JOIN SQL 对比行数与结果集，不一致抛 `140002`。
- **输出**：脱敏任务 ID、脱敏结果统计与 JOIN 验证结果。
- **约束**：脱敏后 JOIN 一致率要求 100%；HMAC 同输入同输出。

### 3.5 FR-05 任务管理与进度

- **描述**：生成与脱敏统一走 `df_task` 任务模型，提供异步执行、取消与 SSE 进度推送。
- **主要输入**：任务类型（GENERATION / MASKING）、连接 ID、配置 JSON、取消请求。
- **处理规则**：
  - 状态机：`PENDING -> RUNNING -> SUCCESS / FAILED / CANCELLED`。
  - 线程池 core 4 / max 8 / queue 100，队列满抛 `150004`，不静默丢弃。
  - 任务取消同时更新内存标志与 `df_task.cancel_requested`；引擎每批处理后检查取消标志主动退出。
  - SSE 位置统一为 `/api/tasks/{id}/progress`，最大连接数 20（超限抛 `150003`），心跳 15 秒，超时 30 分钟；事件类型 `progress` / `log` / `done` / `error` / `heartbeat`。
- **输出**：任务列表、任务详情、SSE 实时进度。
- **约束**：统一响应 `ApiResponse<T>`；任务接口统一为 `/api/tasks/**`。

### 3.6 FR-06 审计

- **描述**：记录本地关键操作，支持按动作与时间追溯。
- **主要输入**：动作（如 `connection_create` / `generation_execute`）、目标、明细、结果、traceId。
- **处理规则**：明细字段中的敏感信息必须已脱敏；结果默认 `success`。
- **输出**：审计日志记录（`df_audit_log`）。
- **约束**：单用户场景也保留审计；禁止记录原始 PII、密码、Token、密钥。

### 3.7 FR-07 鉴权与安全

- **描述**：所有 `/api/**` 接口统一鉴权，并对机密实施加密存储与日志脱敏。
- **主要输入**：请求头 `Authorization: Bearer ${RELIVUS_TOKEN}`。
- **处理规则**：
  - `OncePerRequestFilter` 统一校验 Bearer Token，失败返回 HTTP 401 + `100003`。
  - 连接密码与 AI key 使用 AES-GCM 256 加密；脱敏 HMAC 使用 `RELIVUS_HMAC_KEY`（密钥版本默认 1）。
  - 禁止日志打印原始 PII、密码、Token、密钥；禁止硬编码任何密钥。
- **输出**：鉴权通过后正常响应；否则统一 401。
- **约束**：禁止 `X-Relivus-Token`、Cookie 鉴权、query token 并存；SSE 鉴权同样遵循 Bearer Token（前端使用 `@microsoft/fetch-event-source` 携带）。

### 3.8 FR-08 错误码与统一响应

- **描述**：全系统统一错误码与响应结构。
- **主要输入**：各类业务异常、参数校验失败、系统异常。
- **处理规则**：
  - 错误码采用六位三段式 `A-BB-CCC`：`A` 为责任方（`1` 调用方可修正、`5` 服务端故障），`BB` 为模块域（`00` 通用、`10` 连接、`20` 内省、`30` 生成、`40` 脱敏、`50` 任务、`60` AI），`CCC` 为序号。
  - 统一响应 `ApiResponse` 携带 `code`、`message`、`data`、`traceId`，校验类错误附加 `fieldErrors`。
  - `5xxxxx` 错误对外仅返回通用提示，详情只落服务端日志。
- **输出**：HTTP 4xx / 5xx（`1xxxxx` 映射 4xx 或 502，`5xxxxx` 映射 5xx）。
- **约束**：码值一经发布即冻结，新增需同步更新 `ErrorCode` 枚举、`docs/api-spec.md`（第 4 章码表）与前端 `ERROR_CODE_TEXT`。

## 4. 非功能需求

### 4.1 性能

| 指标 | 阈值 |
|---|---|
| 单表生成行数上限 | 500000 |
| 批量插入批大小 | 默认 1000，可配置（不小于 1） |
| 唯一冲突重试 | 普通列 100 次，低基数列 10 次 |
| 本地唯一值缓存 | Caffeine LRU，最近 10000 个值 |
| 外键采样 | 分页 / 蓄水池，禁止全量加载父表主键 |
| 任务线程池 | core 4 / max 8 / queue 100 |
| AI 批量与重试 | 每批 64 值，仅 5xx / IO / 超时重试 3 次 |
| AI 超时 | 连接 5000ms，读 60000ms |
| 目标连接池 | 最大 20，空闲 10 分钟关闭 |
| 大表目标 | 百万行生成不 OOM |

### 4.2 安全

- 连接密码、AI key 均 AES-GCM 256 密文存储，密钥经环境变量注入。
- 全部接口 Bearer Token 鉴权；SSE 复用同一鉴权方案。
- 禁止日志输出 PII、密码、Token、密钥；审计明细须脱敏。
- 脱敏 HMAC 使用独立密钥 `RELIVUS_HMAC_KEY`，支持密钥版本。

### 4.3 可用性

- 任务可取消，状态可观测（进度、日志、心跳）。
- SSE 断线可重连；执行接口支持 `Idempotency-Key` 幂等。
- 生产环境禁止 Flyway clean，回滚依赖数据库备份恢复。

### 4.4 可维护性

- 包结构与文档按模块划分，接口先行实现。
- 核心包 JaCoCo 行覆盖率不低于 80%。
- 错误码有唯一权威码表与结构契约自校验（`ErrorCodeContractTest`）。

### 4.5 兼容性

- 元库与目标库同时支持 MySQL 8.0 与 PostgreSQL 16，方言自动检测。
- 前端兼容现代浏览器；后端以 systemd + Nginx 裸机部署。

## 5. 数据需求

### 5.1 元库

Relivus 自有库（默认 `relivus_meta`），由 Flyway 管理，存放：

- `df_connection`：目标库连接（密码密文）。
- `df_task`：统一任务（生成 / 脱敏）。
- `df_task_log`：任务日志。
- `df_mask_mapping`：脱敏映射。
- `df_audit_log`：审计日志。
- `df_ai_config`：AI 模型配置（密钥密文）。

详见 [database-design.md](database-design.md)。

### 5.2 目标库

用户自行配置的 MySQL / PostgreSQL 库，是内省、生成、脱敏的操作对象。Relivus 不迁移目标库结构，不改动其 Schema。

### 5.3 目标库准备

目标库由用户自行创建，Relivus 不提供初始化脚本、不迁移目标库结构。本地联调所需的目标表（如 users / orders，覆盖 ENUM、CHECK、UNIQUE、外键）由用户自行准备；集成测试的目标库结构由 Testcontainers 在用例内自建，测试结束随容器销毁，不依赖任何随仓库分发的示例脚本。

## 6. 验收标准

1. `mvn test` 全绿，JaCoCo 核心包覆盖率不低于 80%。
2. 双数据库（MySQL 8.0 / PostgreSQL 16）Flyway 迁移成功，元库表结构语义一致。
3. 双数据库内省成功，可解析表、列、外键、唯一、CHECK、ENUM。
4. 生成 1000 行时外键 100% 有效，唯一约束 0 冲突。
5. 循环依赖外键可空时可成功生成，NOT NULL 时抛 `130003`。
6. 唯一冲突低基数场景抛 `130002`，高基数场景不 OOM。
7. 脱敏后跨表 JOIN 一致率 100%，同一原始值映射一致。
8. 任务可取消，状态可变为 `CANCELLED`；SSE 正常推送，超 20 连接拒绝（`150003`）。
9. 线程池满抛 `150004`。
10. 连接密码与 AI key 不以明文出现在日志和数据库中。
11. 前端六个页面（`/connections`、`/schema/:connId`、`/generation`、`/masking`、`/tasks`、`/settings`）可用，`npm run build` 成功。
12. 后端由 systemd 管理、Nginx 反向代理、无 Docker 部署。
